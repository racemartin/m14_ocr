# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Add durable project-specific notes here as they are discovered through real work.
- `JsonlDatasetRepository` (`src/chsa_triage/infrastructure/adapters/jsonl_dataset_repository.py`) rereads and rewrites the ENTIRE JSONL file on every `sauvegarder()`/`sauvegarder_plusieurs()` call (both dedupe by `identifiant`, dict-keyed). Never call `sauvegarder()` inside a per-item loop over more than a few hundred items — it's O(n²) and infeasible on real corpus sizes (confirmed on the real dataset). Always accumulate into a list and call `sauvegarder_plusieurs()` once. For an append-only audit file where entries may legitimately share an `identifiant` (e.g. `doublons_supprimes.jsonl`), use the module-level `ajouter_exemples_jsonl()` in the same file instead — it appends without the id-merge dedup.
- `LecteurCorpusFichierLocal` loads the whole source file into a pandas DataFrame at once unless constructed with `taille_bloc=N` (chunked pandas read, CSV/JSONL only). Real files here can be ~1GB (`ultramedical_preference.jsonl`, 966MB/109k records) on a ~5.8GB-RAM box — pass `--taille-bloc` (both `profiler_corpus.py --bloque` and `construire_dataset_pivot.py --taille-bloc`) for any source that large, or expect an OOM kill.
- **Pivot/anonymized-file split (since 08/09/2026, decision du capitaine)**: `data/processed/dataset_pivot.jsonl` (the original pivot) is NEVER mutated by `anonymiser_dataset.py` — it's read-only from that point on. Anonymized output goes to a SEPARATE file (`--sortie`, default `dataset_pivot_anonymise.jsonl`). "Already anonymized" is determined by `identifiant` presence in that output file (`RepositoryLectureEcriture.identifiants_existants()`), not by the `anonymise` field on the source pivot (which stays `False` forever on the source). `decouper_splits.py`/`verifier_repartition_splits.py` must point `--dataset` at the ANONYMIZED file, not the original pivot. This design exists so the original text is never lost, enabling `controler_qualite_anonymisation.py` to diff original-vs-anonymized on demand (including retroactively on old waves).
- `ExemplePivot.identifiant` is DETERMINISTIC (sha256 of `espace_noms:cle_naturelle`, see `nouvel_identifiant`), not random — regenerating the pivot from the same `data/raw/` files always produces the same ids. `espace_noms` must be finer than the pivot's `source` field when raw files share a natural-key space: confirmed on real data that `mediqal_oeq.jsonl` and `mediqal_mcqu.jsonl` share 1492 identical raw `id` values for genuinely different records (mcqu vs mcqm distinguished via the raw `task` field). `ConstruireDatasetPivotUseCase` treats two raw records that hash to the same `identifiant` as true exact duplicates and drops all but the first, archiving the dropped ones (never silently) to `data/processed/doublons_supprimes.jsonl` via `ajouter_exemples_jsonl`. Real counts found this way: FrenchMedMCQA 1/595, MedQuAD 48/16407, UltraMedical-Preference 12272/109353 — see `docs/02_etape1_donnees/00_couverture_exigences_officielles.md` for the per-source natural-key design and the dedup investigation.
- Real Presidio/spaCy anonymization throughput measured on the real dataset: ~130-550ms per text field depending on length/language, dominated by spaCy NLP inference, not I/O. Full-dataset anonymization is estimated at ~19h wall time with the current per-field `AnalyzerEngine.analyze` calls (no batching). `anonymiser_dataset.py --limite N` (default 5000) makes this incremental/resumable via the pivot/anonymized-file split above. See `docs/02_etape1_donnees/00_couverture_exigences_officielles.md` for the measured breakdown and wave history.
- `data/raw/`, `data/processed/`, `data/splits/` are gitignored — a fresh worktree/clone has none of the 6 source files. Regenerate them with the `telecharger_corpus.py` commands in the README before running any later pipeline step; no network access means the pipeline literally cannot be exercised end-to-end.
- Regenerating `docs/diagrams/**/*.puml` outputs: this box has no `plantuml` CLI and no matching-JDK PlantUML jar preinstalled (system Java is 17; the latest PlantUML jar needs Java 21 for its PDF path, throwing `UnsupportedClassVersionError`). Workaround that worked: download an older jar built for Java 17 (e.g. `plantuml-1.2024.8.jar` from GitHub releases) for `-tpng -tsvg` (run those two together, not combined with `-tpdf` — a PDF failure aborts the whole invocation before png/svg get written), then convert the generated `.svg` to `.pdf` with `cairosvg` (`uv pip install --python <venv> cairosvg`, needs system `libcairo2` which is present) since PlantUML's own PDF export needs Apache Batik+FOP transcoders not bundled in the jar.
