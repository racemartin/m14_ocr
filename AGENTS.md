# Development notes

This file is the project's committed home for build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Add durable project-specific notes here as they are discovered through real work.
- **File naming convention `E1_NN[_MM]_verbe_objet.py` / `E2_NN_uc_verbe_objet.py` (since 11/09/2026)**: Étape 1's CLI scripts (`interfaces/cli/`), use cases (`src/chsa_triage/application/use_cases/`) and their tests were renamed from the old `uc_0X_...`/unprefixed pattern to `E1_NN[_MM]_verbe_objet.py`, `NN` matching the pipeline step (`01` téléchargement, `02` profilage, `03` pivot, `04` anonymisation/QC, `05` splits/SFT) and `_MM` disambiguating sibling files within the same step (e.g. `E1_03_00_construire_dataset_pivot.py` + `E1_03_01_mappers_corpus.py`). Étape 2's use cases (`E2_00_uc_formater_dataset_chatml.py` through `E2_03_uc_sauvegarder_checkpoint_sft.py`) add a `_uc_` marker right after the number, reserved for actual use-case classes only: the two pure functions of the same phase (`application/verdict_convergence.py`, `application/grille_hyperparametres.py`) live outside `use_cases/` and carry no numeric prefix at all, same pattern as `application/echantillonnage.py`/`application/detection_pii_residuelle.py` in Étape 1. The `_uc_`/numeric-prefix marker is a filename-only convention: it never appears in the Python class/function names themselves.
- `JsonlDatasetRepository` (`src/chsa_triage/infrastructure/adapters/jsonl_dataset_repository.py`) rereads and rewrites the ENTIRE JSONL file on every `sauvegarder()`/`sauvegarder_plusieurs()` call (both dedupe by `identifiant`, dict-keyed). Never call `sauvegarder()` inside a per-item loop over more than a few hundred items; it's O(n²) and infeasible on real corpus sizes (confirmed on the real dataset). Always accumulate into a list and call `sauvegarder_plusieurs()` once. For an append-only audit file where entries may legitimately share an `identifiant` (e.g. `doublons_supprimes.jsonl`), use the module-level `ajouter_exemples_jsonl()` in the same file instead: it appends without the id-merge dedup.
- `LecteurCorpusFichierLocal` loads the whole source file into a pandas DataFrame at once unless constructed with `taille_bloc=N` (chunked pandas read, CSV/JSONL only). Real files here can be ~1GB (`ultramedical_preference.jsonl`, 966MB/109k records) on a ~5.8GB-RAM box; pass `--taille-bloc` (both `E1_02_profiler_corpus.py --bloque` and `E1_03_00_construire_dataset_pivot.py --taille-bloc`) for any source that large, or expect an OOM kill.
- **Pivot/anonymized-file split (since 08/09/2026)**: `data/processed/dataset_pivot.jsonl` (the original pivot) is NEVER mutated by `E1_04_00_anonymiser_dataset.py`; it's read-only from that point on. Anonymized output goes to a SEPARATE file (`--sortie`, default `dataset_pivot_anonymise.jsonl`). "Already anonymized" is determined by `identifiant` presence in that output file (`RepositoryLectureEcriture.identifiants_existants()`), not by the `anonymise` field on the source pivot (which stays `False` forever on the source). `E1_05_00_decouper_splits.py`/`E1_05_01_verifier_repartition_splits.py` must point `--dataset` at the ANONYMIZED file, not the original pivot. This design exists so the original text is never lost, enabling `E1_04_02_controler_qualite_anonymisation.py` to diff original-vs-anonymized on demand (including retroactively on old waves).
- `ExemplePivot.identifiant` is DETERMINISTIC (sha256 of `espace_noms:cle_naturelle`, see `nouvel_identifiant`), not random: regenerating the pivot from the same `data/raw/` files always produces the same ids. `espace_noms` must be finer than the pivot's `source` field when raw files share a natural-key space: confirmed on real data that `mediqal_oeq.jsonl` and `mediqal_mcqu.jsonl` share 1492 identical raw `id` values for genuinely different records (mcqu vs mcqm distinguished via the raw `task` field). `ConstruireDatasetPivotUseCase` treats two raw records that hash to the same `identifiant` as true exact duplicates and drops all but the first, archiving the dropped ones (never silently) to `data/processed/doublons_supprimes.jsonl` via `ajouter_exemples_jsonl`. Real counts found this way: FrenchMedMCQA 1/595, MedQuAD 48/16407, UltraMedical-Preference 12272/109353; see `docs/02_etape1_donnees/00_couverture_exigences_officielles.md` for the per-source natural-key design and the dedup investigation.
- Real Presidio/spaCy anonymization throughput measured on the real dataset: ~130-550ms per text field depending on length/language, dominated by spaCy NLP inference, not I/O. Full-dataset anonymization is estimated at ~19h wall time with the current per-field `AnalyzerEngine.analyze` calls (no batching). `E1_04_00_anonymiser_dataset.py --limite N` (default 5000) makes this incremental/resumable via the pivot/anonymized-file split above. See `docs/02_etape1_donnees/00_couverture_exigences_officielles.md` for the measured breakdown and wave history.
- `SpacyVerificateurEntitesNommees.verifier()` (`src/chsa_triage/infrastructure/adapters/spacy_verificateur_entites.py`) caches the parsed spaCy `Doc` keyed by `(texte, langue)` in a small LRU (8 entries): `E1_04_02_controler_qualite_anonymisation.py` calls `verifier()` once per candidate found in a field, passing the same full text each time (measured up to 17 calls for one UltraMedical-Preference field), so without the cache the same text gets reparsed by spaCy repeatedly. Microbenchmark on a realistic text (17 repeat calls): ~0.12s cached vs ~1.24s uncached.

- **Persisted human review of PII-residual candidates (since 09/09/2026, NF2)**: `E1_04_02_controler_qualite_anonymisation.py`'s sampling is now INCREMENTAL: `--registre-echantillons` (default `data/processed/controle_qualite_identifiants_echantillonnes.jsonl`, `JsonlRegistreEchantillonsControleQualite`) excludes identifiants already sampled in a prior run, on both strata (`STRATUM_PRINCIPAL`/`STRATUM_SANS_ENTITE`), same pattern as `AnonymiserDatasetUseCase`/`--limite`. A candidate's stable key across runs is `CleCandidatRevision(source_liste, identifiant, champ, type_motif, debut, fin)` (`domain/model/decision_revision_humaine.py`); `source_liste` disambiguates the 3 candidate lists (`candidats_pii`/`candidats_faux_positifs`/`candidats_pii_sans_entite`) since the same `CandidatPiiResiduelle` dataclass backs two of them. Human decisions (`accepte`/`rejete`) persist in `data/processed/decisions_revision_humaine.jsonl` (`JsonlDecisionsRevisionHumaine`, upsert-by-key like `JsonlDatasetRepository.sauvegarder`, not append-only, since `--modify` corrects mistakes). `interfaces/cli/E1_04_01_reviser_pii_residuelle.py verify` replays the comparison over the FULL cumulative sampled set (not just the latest QC report, which only covers that run's fresh batch) to surface every still-pending `VERDICT_REVISION_HUMAINE` candidate; this is why `ControleQualiteAnonymisation.max_faux_positifs_par_source` accepts `None` (unlimited) now, vs. the default cap of 10 used for the human-readable Markdown report. See `docs/02_etape1_donnees/01_rapport_rgpd.md` §7.5 for the full design rationale.
- **`E1_05_00_decouper_splits.py --n` is a cumulative TARGET size, not a fresh-sample size, since 10/09/2026**: `DecouperSplitsUseCase` never reassigns the `split` of an `ExemplePivot` that already has one from a prior run; only examples with `split is None` are candidates. `--n N` pulls `N - (already assigned)` new examples (stratified sample among the unsplit candidates); omitting `--n` completes all remaining unsplit examples rather than recomputing everything. This replaces an earlier design where every run reshuffled ALL considered examples, which could silently move an example from `train` to `test` (or back) across runs: a train/test leak. `E1_05_00_decouper_splits.py --dataset ... --n 5000` then later `--n 10000` on the same file leaves the first 5000 assignments untouched; `nombre_deja_assignes`/`nombre_nouveaux` on the use case distinguish prior-run vs this-run counts, and the returned dict is the cumulative total, not just this run's additions. `E1_05_01_verifier_repartition_splits.py` needed no change; it just reads whatever splits currently exist. See `docs/02_etape1_donnees/00_couverture_exigences_officielles.md` ("Croissance stable...") for the full rationale and the two-alternatives comparison, and the module docstring of `E1_05_00_decouper_splits.py` for the algorithm.
- **Publication exclusion of PII-residual candidates, two-step (since 11/09/2026)**: before publishing the SFT subset, `E1_04_01_reviser_pii_residuelle.py exporter` (a third, non-interactive CLI mode alongside `verify`/`modify`) writes `data/processed/identifiants_a_exclure_publication.jsonl` (`--sortie`), one `{identifiant, razon}` line per identifiant with at least one `VERDICT_CONFIRME` candidate (razon `confirme`) or one `VERDICT_REVISION_HUMAINE` candidate without a persisted `DECISION_ACCEPTE` (razon `pendant_revision_humaine`; `confirme` wins when an identifiant has both). Reuses the same replay engine as `verify` (`ReviserPiiResiduelleUseCase._rejouer_controle`, generalized `candidats_a_revoir(controle, verdicts=...)`), extended to also surface `VERDICT_CONFIRME`, which `verify`/`candidats_en_attente()` never did (those candidates are unambiguous regex hits and never go through human decision). `interfaces/cli/E1_05_02_extraire_sous_ensemble_sft.py --dataset --exclusions --taille --sortie` then filters the anonymized pivot on `type_exemple == TypeExemple.SFT` and `split is not None` minus that exclusion file (`ExtraireSousEnsembleSftUseCase`, `E1_05_02_extraire_sous_ensemble_sft`); it is a filter/subtraction, never a re-sampler in the sense of never drawing NEW examples to make up a shortfall: if the result is short of `--taille` it reports the shortfall and tells you to widen `E1_05_00_decouper_splits.py --n` first, rather than silently returning fewer examples. See README §9 for the full two-command flow.
- **`E1_05_02_extraire_sous_ensemble_sft.py` truncates a surplus to exactly `--taille` (fixed 11/09/2026)**: an earlier version only ever subtracted and never trimmed, so a filtered result larger than `--taille` (e.g. 9926 available for a requested 5000) was written in full, silently publishing more than asked. `ExtraireSousEnsembleSftUseCase.executer()` now applies `echantillon_stratifie` (`application/echantillonnage.py`, the same plus-grand-reste algorithm used by `AnonymiserDatasetUseCase`/`DecouperSplitsUseCase`) when the post-exclusion result exceeds `taille_cible`, so the written count is exactly `taille_cible` whenever enough examples are available; `nombre_disponible_final` still reports the pre-truncation pool size (used by `manque`), while the new `nombre_tronque` reports how many were cut. `echantillon_stratifie` does not stratify by `split`, only by `(type_exemple, source)`; confirmed empirically (not assumed) in `tests/application/test_extraire_sous_ensemble_sft.py` that a random sub-sample of an already-~80/10/10 stratum stays within a few points of 80/10/10 without a second nested stratification layer. The CLI prints a per-strate `Strate | Total | train (%) | val (%) | test (%)` table of the WRITTEN result (`calculer_repartition_par_strate`/`formater_tableau_repartition`, E1_05_02_extraire_sous_ensemble_sft), same presentation as `E1_05_01_verifier_repartition_splits.py` but computed in-memory rather than by rereading the repository.
- **SFT/DPO type leak into the "SFT" outputs (fixed 12/09/2026)**: `ExtraireSousEnsembleSftUseCase.executer()` and `FormaterDatasetChatMLUseCase.executer()` used to filter only on `split` (resp. `split is not None` and `split == <split demande>`), never on `type_exemple`. `DecouperSplitsUseCase` (§ above) deliberately assigns splits to BOTH `TypeExemple.SFT` and `TypeExemple.DPO` examples in the same anonymized pivot file, so DPO examples (`chosen`/`rejected` populated, `completion` empty; UltraMedical-Preference is the only DPO source) were leaking into files/renders meant to be SFT-only. Confirmed on real data before the fix: a 5000-row "SFT" export was 72% DPO (3599/5000). Both use cases now filter explicitly on `type_exemple == TypeExemple.SFT` before doing anything else. Consequence: `E1_05_02_extraire_sous_ensemble_sft.py --taille N` now counts against the SFT-only pool, which can be much smaller than the full split-assigned pool; `--taille` was always a ceiling (cf. truncation note below) and is now more often the binding constraint from the other side (`manque` > 0). The output filename (`chemin_sortie_defaut`) still encodes `--taille`, not the real row count: rename the written file to match its actual line count before publishing (README §9 does this by hand), so a filename never overstates what it contains. Once the pivot is FULLY anonymized and split (134 883 rows, 37 802 SFT/97 081 DPO; a from-scratch worktree only has whatever `E1_04_00_anonymiser_dataset.py --limite N` waves were actually run, cf. the incremental-anonymization note above), the SFT pool is large enough that `--taille 5000` is met exactly with no rename needed; the shortfall/rename case above only bites when anonymization+split coverage is still partial.

- **`ChatMLFormateurAdapter.formater_preference()`'s `<think>` bug, root cause and fix (19/09/2026)**: root cause pinned down by reading Qwen3's real chat template jinja (`tokenizer.chat_template`, installed temporarily, same method as everywhere else in this project): the template computes `last_query_index` (the index of the last `user` message) and only re-injects `<think>...</think>` for an assistant message whose `loop.index0 > last_query_index`; the old `_rendre_tour_assistant_seul` called `apply_chat_template` on the assistant turn ALONE (no preceding `user` message in the list), so `last_query_index` defaulted to that lone message's own index, the condition was false, and the template used the post-`</think>` `content` only, dropping the reasoning.
